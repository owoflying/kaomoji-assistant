# 材质系统重做方案（基于 DS H wallpaper 插件的正确做法）

## 参考实现

`~/.dsh/profiles/desktop/node_modules/dsh-plugin-wallpaper-engine/lib/client.js`

核心做法（CSS）：

```css
backdrop-filter: blur(var(--we-blur, 16px))
                 saturate(var(--we-saturate, 1.8))
                 brightness(var(--we-glass-brightness, 1.04))
                 contrast(1.01);
```

配套变量：

    --we-glass-alpha       玻璃透明度（0~0.5）
    --we-surface-tint-*    玻璃基色（随明暗不同）
    --we-blur              模糊半径
    --we-readability-floor 可读性保底（保证文字看得清）

关键洞察：**`backdrop-filter` 模糊的是"元素背后实际显示的内容"**，
所以卡片背后是真背景图，模糊是真实时算的。

## 我的实现错在哪

我做的是"预渲染一张模糊图，贴到卡片上"。两者本质不同：

| | 正确做法 | 我的做法 |
|---|---|---|
| 模糊对象 | 卡片**背后**的实际像素 | 独立生成的一张图 |
| 视觉结果 | 透过卡片看到模糊的背景 | 卡片只是半透明，看到**未模糊**的背景 |
| 文字可读性 | 有 readability-floor 保底 | 无保证 |

所以用户说"卡片按钮的高级材质完全没有一点效果"——因为卡片只是变半透明，
背后的背景图并没有被模糊，视觉上就没有"毛玻璃"的质感。

## 用户报告的另一个 bug：透明度调了不变

    拉不透明度到 0     → 面板还是灰色
    拉图片不透明度到 0 → 还是不透明
    调背景暗化/提亮到 0 → 突然透明了
    再调配置          → 又不透明了
    重复一遍          → 还是不透明
    反复拉几下        → 又透明了

这是**状态互相覆盖**。可能原因：

1. `material_image_opacity=0` 时，背景图画不上去，但面板底色又不透明，
   于是看起来是"纯灰"——用户以为没生效
2. 面板底色 `panel_alpha` 与 `_adjusted_panel_base` 之间还有残留耦合
3. 暗化/提亮为 0 时走了某个分支跳过了底色绘制

## Qt 里如何实现 backdrop-filter 等价物

Qt 没有 CSS backdrop-filter。等价做法：

### 方案 A：分层预渲染（推荐）

把窗口背景**先渲染到一个 QPixmap**（含背景图 + 材质模糊），
然后：
- 窗口 paintEvent 画这张图
- 卡片 paintEvent **从这张图里裁出自己区域的对应部分**并贴上去

这样卡片显示的确实是"背后那块背景"（已模糊），效果等同于
backdrop-filter 的静态版本。

关键：卡片位置变了要重新裁剪，但模糊只需算一次。

### 方案 B：每张卡片独立模糊背后区域

卡片计算自己的全局位置，从背景原图裁出对应区域，**单独模糊**。
更准确（不同卡片可以有不同的模糊强度），但每张卡片一次模糊，
一页十几张卡片会卡。

### 方案 C：QGraphicsBlurEffect 叠加

不适用——它模糊的是控件自身内容，不是背后。

## 决定

用**方案 A**：背景图只模糊一次，卡片从结果里裁。

## 同时要修的

1. 透明度三条滑块彻底解耦，任何一个为 0 都不能让画面"卡住"
2. 参考 wallpaper 的 `readability-floor`：材质开启时给卡片一个最低不透明度，
   保证文字可读
3. 卡片材质必须真的显示出"背景被模糊"，否则和没有一样
